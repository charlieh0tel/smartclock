# The HP 53131A family and the SmartClocks

The HP 53131A and 53132A universal counters, and the 53181A, are built
on the same platform as the SmartClock receivers: the same processor,
FPGA, EEPROM, reset supervisor and DAC, the same pSOS kernel glue from
the same HP source files, and the same SCPI parser.  This page records
what that is established from, and what it could tell us about the
receivers.

Sources: xdevs.com's page on the family,
<https://xdevs.com/fix/hp5313X/>, with its firmware dumps, service
manuals and component-level information (CLIP) documents, among them
<https://xdevs.com/doc/HP_Agilent_Keysight/53131A/53131A_CLIP.pdf>.
None of them is copied into this repository.

## The parts

From the 53131A CLIP's parts lists, beside the Z3805A's
([`z3805a-board.html`](https://htmlpreview.github.io/?https://github.com/charlieh0tel/smartclock/blob/main/docs/z3805a-board.html)):

| Part | 53131A | Z3805A |
| ---- | ------ | ------ |
| MC68331, 16 MHz, 32.768 kHz crystal | U7, MC68331CEH16 | U33, MC68331CFC16 |
| XC3042 FPGA | U58, XC3042A-7PC84C | U32, XC3042-70 PC84C |
| AT28C64B EEPROM | U14, AT28C64B-15JU | U4, AT28C64B-20JC |
| TL7705A reset supervisor | U25 | U28 |
| MC144110 6-bit DAC | U4, MC144110DWR2 | U37 |
| Flash or EPROM | AM29F400 (U8a, later boards); four AM27C010 (3944 dump) | four AM29F010 |

The counter has a GPIB controller (U20) as well as RS-232.  The 53132A
fits a second XC3042A (U59), a voltage reference and two ADCs that the
53131A leaves empty.

## The 3944 firmware

The 53131A's revision 3944 dump is four AM27C010 EPROMs, U8 to U11,
as Intel hex.  U8 and U10 are the lower 256 KiB bank and U9 and U11
the upper, each word's high byte from the first of each pair.  So
joined, it is a 512 KiB image whose reset vector gives a supervisor
stack of `0x10fffe`, the receivers' own, and its copyright reads
"Hewlett-Packard Co. 1993".

**The same source files.**  Both images carry RCS headers for the
pSOS glue, by the same author:

| File | 53131A 3944 | Z3805A 3543B |
| ---- | ----------- | ------------ |
| `psos.S` | 1.2, 1992-08-28 | 1.4, 1995-01-11 |
| `dev_tab.S` | 1.4, 1992-08-28 | 1.8, 1995-01-11 |
| `psos_indep.h` | 1.1, 1992-01-10 | 1.5, 1995-03-24 |

So the receivers' firmware and the counter's are one HP codebase, the
counter's the older.

**A pForth console.**  The counter's service menu lists `PFORTH:`
beside `DEBUG O/P:`, `DEBUG OS:` and `GPIB BUF:` (`0x30209`), as the
receivers carry a pForth console ([`firmware/console.md`](firmware/console.md)).

## What the tools make of it

**The SCPI tree.**  `smartclock-cli dump-scpi` reads the image's tree
without error, 699 paths, among them `*_TRG?`, the common command
whose underscore `dump-scpi` once refused.  Most of the counter's
keywords that take a numeric suffix are alias nodes: two sibling
nodes, the short form and the long form, each a whole keyword, which
the receivers use for `SERial` and a few others
([`scpi/README.md`](scpi/README.md), "Alias nodes").  `dump-scpi`
lists each such pair once, `:CALCulate`, `:CALCulate1` to
`:CALCulate3`, `:INPut`, `:CALibration`; before it did, they came out
as two parallel subtrees, `:CALC` beside `:CALCULATE`, and the tree as
1167 paths.

## The 53132A's 4613 firmware

The 53132A's revision 4613 dump is xdevs.com's
`Agilent_53132A_Counter_Timer_53132A_ROMS_4613.zip`: four AMD 27C010
EPROMs, U8 to U11 (53132-80033 to -80036), as raw binaries.  They join
as the 3944's do, U8 the high and U10 the low byte of the lower
256 KiB bank, U9 and U11 the upper, into a 512 KiB image whose reset
vector gives a supervisor stack of `0x10fffe`.

`dump-scpi` reads its tree as 756 paths, 1330 with alias nodes kept.
`:CALCulate` is `CALC\0\0` (`0x4de5a`) and `CALCULATE\0\0`
(`0x4de4f`), `:INPut` `INP\0\0` (`0x4e555`) and `INPUT\0\0`
(`0x4e54e`), each pair two nodes sharing one child list, where
`:SYSTem` and `:STATe` are each one keyword pair, `SYST\0EM\0`.

**A live counter.**  A 53132A running it answers `*IDN?` with
`HEWLETT-PACKARD,53132A,0,4613` and `:SYST:VERS?` with `1992.0`.  It
takes either alias: `:CALC1:MATH:STAT?` and `:CALCULATE1:MATH:STATE?`
both answer, and `:CALCU1:MATH:STAT?`, neither form, is refused with
-113, "Undefined header".  So the two nodes are one keyword's two
spellings, and nothing between them is taken.

**The FPGA bitstreams.**  The repository has no tool that finds a
bitstream in an image: the five in `third_party/firmware/fpga/` were
cut out by hand.  A scan for the XC3000 header, `ff`, then `2`, a
24-bit length count and `f`, finds three full XC3042 bitstreams in the
3944 image, at `0xd906`, `0xe81a` and `0xf72e`, 3860 bytes apart, each
with the length count 30828, the Z3805A's, and a fourth header at
`0x1065c` with 30830.  The same scan also matches unrelated bytes (one
in the 3944 image, several in the Z3805A's), so a header alone is not
enough.

## Further investigation

- **The SCPI keyword encoding.**  Done: a keyword with a numeric
  suffix is two alias nodes, and `dump-scpi` prints each pair once, in
  mixed case, with a synthetic test ("The SCPI tree", above).  Left:
  check the listing against the 53131A's programming guide.
- **A bitstream extractor.**  A `smartclock-cli` command that finds
  each image's bitstreams by following the firmware's own
  configuration table (`fpga_configurations`, `0x21e2c` in the Z3805A;
  [`firmware/outputs.md`](firmware/outputs.md), "The FPGA bitstreams")
  where there is one, rather than trusting a header scan, and writes
  each as a `.bit`.  The 3944 image's three configurations would then
  say what each of the counter's designs is for.
- **Names by comparison.**  Diff the 3944 image against the Z3805A's
  to name the shared routines (the pSOS glue,
  the C library, the SCPI engine, pForth); the 1992 versions may show
  why some of the receivers' routines are as they are.
- **The schematics by analogy.**  Read the CLIP's schematics for what
  the receivers' bench items ask
  ([`hardware-investigations.md`](hardware-investigations.md)): the
  MC144110's supply (item 23), the XC3042's pins and where its clock
  and 1 PPS lines go, where the TL7705A's reset goes (item 20), the
  BDM header (J12, item 13), and the EEPROM's select (item 22).  A
  different board shows how HP wired the platform, not how a receiver
  is wired; the bench settles that.
- **The other dumps.**  The 53181A's dumps, the same way, and the
  53132A's 4613 beyond its SCPI tree.
- **The compiler.**  The receivers' compiler is unknown
  ([`firmware/README.md`](firmware/README.md), "The calling
  convention"); an earlier build of the same codebase may carry a
  banner, a runtime library or a calling convention that names it.
